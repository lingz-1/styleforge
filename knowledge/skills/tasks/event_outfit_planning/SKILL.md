# Event Outfit Planning（活动 / 出行穿搭规划）

## 适用场景

用户穿搭需求涉及**具体现实世界事件**：演出、音乐剧、戏剧、演唱会、展览、漫展、会议、展会、赛事、节庆、晚宴、婚礼、旅行目的地等。

这类请求不能仅凭活动名称猜测，必须先获得**可靠的外部事实**，再把事实转化为穿搭决策。

## 工作流程

1. **识别活动实体**
   - 活动名称（专有名词）
   - 时间（哪一天 / 时段）
   - 地点（城市 / 场馆）
   - 用户参与方式（观众 / 参展 / 参会 / 游玩）

2. **判断缺少哪些事实**（不要假设自己知道）
   - 举办日期
   - 场馆 / 具体场地
   - 活动性质与正式程度
   - 官方 dress code 或入场 / 服装限制
   - 是否长时间步行（漫展 / 展会 / 音乐节）
   - 室内还是室外
   - 活动主题 / 视觉风格

3. **对动态事实使用 search_web**（信息获取决策，不是关键词规则）
   - 优先：官方活动页 > 场馆 / 主办方 > 可靠第三方报道
   - 把「专有名词 + 时间 / 地点」当作未知新实体去查，不凭内部知识编造细节
   - 搜索目的不是查「有没有 dress code」，而是**判断活动性质、主题、氛围、场地与时效信息**，据此推导怎么穿才符合主题

4. **天气会影响穿着时调用 get_weather**
   - 有明确地点 + 日期时查当地天气（室外活动、长时间步行、早晚温差尤其需要）

5. **把事实转化为穿搭需求**（不要直接复制搜索文本）
   - formal / casual 正式度
   - 行走舒适度（鞋履）
   - 叠穿与层次（室内外温差）
   - 色系 / 风格方向（活动主题元素）
   - 实际限制（禁止某类服装、需要庄重等）

6. **检索用户衣橱**：search_wardrobe 按上述需求检索单品（中英文表达都试）

7. **组合搭配**：选择满足场景、主题与舒适度的单品，组合完整搭配

8. **说明决策来源**：在理由里写明「哪条来自活动事实、哪条来自天气、哪条来自用户需求」，
   而不是简单说「看音乐剧建议穿裙子」

## 边界

- Skill 只教**如何调查与决策**，不决定具体穿什么；搜索什么、查几次、最后怎么搭由 Agent 自主决定。
- 搜索结果仅作知识参考，item_id 必须来自衣橱检索结果，绝不用联网返回的商品充当衣橱单品。
- 简单修改请求（换双鞋、休闲一点）不需要本流程，直接行动。
