# 项目计划书：StyleForge v3.1 —— 多智能体穿搭决策系统

> **版本：v3.1** | **日期：2026年7月21日**
>
> **一句话定位**：基于 LangGraph 的多智能体决策系统，在时尚约束优化任务上的工程实现。


## 一、项目概述

### 1.1 项目定位

StyleForge v3.1 是一个**多智能体穿搭决策系统**，而非传统的“推荐系统”或“聊天机器人”。它的核心任务不是“推荐衣服”，而是**在结构化约束空间中进行搜索与优化，输出可解释的穿搭方案**。

系统通过 **7 个 Agent/模块** 协作完成从用户意图理解到穿搭方案输出的完整链路，核心差异化在于：

- **可解释评分**：Critic 采用确定性规则，每个分数都可追溯
- **可插拔知识库**：风格技能包（Style Skills）和配色方案库（Color Palettes）独立配置
- **闭环迭代修复**：Critic ↔ Repair 最多 3 轮，实现“手术式”局部优化

### 1.2 核心设计哲学

| 原则 | 说明 |
|------|------|
| **认知分工** | 每个 Agent 承担独立的认知职责，不是“角色扮演 Prompt 拆分” |
| **约束优化** | 问题本质是“在受限单品池中搜索满足多目标约束的组合” |
| **确定性锚点** | Critic 采用硬编码规则，保证评分可解释、可复现 |
| **局部修复** | 失败时采用“手术式”局部替换，而非全局重生成 |
| **知识可插拔** | 风格规则和配色方案以配置文件形式独立管理，无需改代码 |

### 1.3 系统类型定义

```
这不是：   ❌ “多角色 LLM 流水线”
这是：     ✅ “多智能体决策系统”
关键区别：  每个 Agent 有独立策略/状态/工具，通过结构化事件通信
```

### 2.2 核心数据流（端到端）

```
用户输入：“明天面试穿什么？”
    │
    ▼
【Intent Planner】→ 任务图 {occasion: "面试", constraints: ["正式", "中性色"]}
    │
    ▼
【知识层匹配】→ 匹配 Style Skill（商务正装）+ Color Palette（商务配色）
    │
    ▼
【Style Strategy】→ 风格分布 {formal: 0.7, business_casual: 0.2, minimalist: 0.1}
    │                 + 受 Style Skill 约束
    ▼
【Retriever】→ 硬过滤（正式度≥6）+ Skill 约束 + 向量检索 → Top-30
    │
    ▼
【Composer】→ LLM 生成 3 套方案（受 Skill + Palette 约束）
    │
    ▼
【Critic】→ 4维评分 + Palette 适配度（新增）+ Skill 适配度（新增）
    │
    ├── PASS (≥75) → 输出 3 套方案 + 评分报告
    │
    └── FAIL (<75) → 结构化报错 → 【Repair】→ 局部替换 → 回到 Critic
                         │
                         └── 最多 3 次迭代 → 熔断 → 输出次优方案
```

### 3.2 Style Skills（风格技能包）

**定位**：每个 skill 是一个风格流派的完整规则包，包含单品约束、色彩规则、正式度范围、材质偏好等。

**文件组织**：
```
skills/
├── business_formal.yaml          # 商务正装
├── business_casual.yaml          # 商务休闲
├── smart_casual.yaml             # 精致休闲
├── minimalist.yaml               # 极简主义
├── street_style.yaml             # 街头风格
├── vintage.yaml                  # 复古风格
├── sporty.yaml                   # 运动风格
├── bohemian.yaml                 # 波西米亚
├── date_night.yaml               # 约会穿搭
└── default.yaml                  # 默认通用规则
```

**单个 skill 文件结构**（以 `business_formal.yaml` 为例）：

```yaml
skill_id: business_formal
name: 商务正装
description: 适用于面试、商务会议等正式场合
applicable_occasions:
  - 面试
  - 商务会议
  - 正式晚宴

# ===== 单品约束 =====
category_rules:
  top:
    allowed: [衬衫, 西装外套, 马甲]
    forbidden: [T恤, 卫衣, 背心,  Polo衫]
  bottom:
    allowed: [西裤, 铅笔裙, 直筒裙]
    forbidden: [牛仔裤, 短裤, 运动裤, 工装裤]
  shoes:
    allowed: [牛津鞋, 乐福鞋, 尖头高跟鞋]
    forbidden: [运动鞋, 凉鞋, 拖鞋, 帆布鞋]
  outerwear:
    allowed: [羊毛大衣, 风衣]
    forbidden: [羽绒服, 牛仔夹克, 棒球服]
  accessory:
    allowed: [领带, 丝巾, 简约手表]
    forbidden: [棒球帽, 夸张项链, 运动手环]

# ===== 色彩规则 =====
color_rules:
  primary_colors: [黑色, 白色, 灰色, 藏青色, 深棕色]
  accent_colors: [酒红色, 深绿色, 暗金色]

  saturation_max: 40

# ===== 数值约束 =====
formality_range: [7, 9]
color_contrast_min: 20  # 明度差最小值

# ===== 材质偏好 =====
material_rules:
  preferred: [羊毛, 棉, 丝绸, 精纺]
  forbidden: [牛仔布, 运动面料, 涤纶, 尼龙]

strictness: 0.85  # 1=严格执行，0=仅参考
```

```python
class StyleSkill(BaseModel):
```

### 3.3 Color Palettes（配色方案库）

**定位**：预定义的色彩搭配方案，每个方案定义色相组合规则和适用场景。

**文件组织**：
```
palettes/
├── monochrome.yaml               # 单色搭配
├── complementary.yaml            # 互补色搭配
├── analogous.yaml                # 邻近色搭配
├── triadic.yaml                  # 三角形搭配
├── split_complementary.yaml      # 分裂互补色搭配
├── tetradic.yaml                 # 矩形搭配
├── warm.yaml                     # 暖色调
├── cool.yaml                     # 冷色调
├── neutral.yaml                  # 中性色
└── custom_templates.yaml         # 用户自定义模板
```

**单个配色方案文件结构**（以 `complementary.yaml` 为例）：

```yaml
palette_id: complementary
name: 互补色搭配
description: 色相环上相对的两个颜色，视觉冲击力强
type: complementary

# ===== 色彩规则 =====
color_rules:
  hue_difference: [150, 180]      # 色相差范围（度）
  saturation_mode: balanced       # balanced / dominant_subtle
  value_contrast: high            # high / medium / low
  recommended_pairs:
    - [红色, 绿色]
    - [蓝色, 橙色]
    - [黄色, 紫色]
  
# ===== 明度规则 =====
value_rules:
  dominant_value: [60, 80]
  accent_value: [30, 50]
  value_diff_min: 30

# ===== 适用场景 =====
applicable_occasions:
  - 约会
  - 创意行业
  - 休闲社交
  - 春夏季节

# ===== 饱和度建议 =====
saturation:
  recommended: [40, 70]
  max: 80
```

**数据结构定义**：

```python
class ColorPalette(BaseModel):
    palette_id: str
    name: str
    description: str
    type: str  # monochrome / complementary / analogous / triadic / ...
    
    # 色彩规则
    color_rules: Dict[str, Any]
    
    # 明度规则

    # 适用场景

    # 饱和度建议

```

```python
    """统一的技能与配色加载器"""

        self._load_all(skills_dir, palettes_dir)

        # 加载所有 skill
        for yaml_file in Path(skills_dir).glob("*.yaml"):
            skill = self._parse_skill(yaml_file)
            self.skills[skill.skill_id] = skill

        for yaml_file in Path(palettes_dir).glob("*.yaml"):
```

### 3.5 知识层在系统中的集成点

| Agent/模块 | 集成方式 |
|-----------|---------|
| **Intent Planner** | 识别 occasion 后，触发知识层匹配 |
| **Style Strategy** | 输出风格分布时受 Skill 约束裁剪 |
| **Retriever** | 应用 Skill 中的硬约束（允许/禁止品类、正式度范围、材质偏好） |

## 五、多智能体详细设计

### 5.1 Agent 1：Intent Planner Agent（意图规划器）

**类型**：LLM Agent

**职责**：将模糊的用户自然语言转化为结构化任务图，并触发知识层匹配。

**输入**：
```json
{
  "user_query": "明天面试穿什么？",
  "user_state": {
    "preferred_styles": ["简约", "商务"],
    "avoided_categories": ["牛仔", "运动鞋"]
  }
}
```

**处理流程**：
1. 解析用户意图，提取场合
2. 调用知识层匹配 Style Skill 和 Color Palette
3. 生成结构化任务图

**输出**：
```json
{
  "occasion": "面试",
  "formality_target": 7.5,
  "style_intent": "formal + safe",
  "constraints": ["禁止牛仔裤", "中性色为主", "正式度≥6"],
  "risk_level": "low",
  "fallback_strategy": "若正式方案失败，降级为商务休闲",
  "matched_skills": ["business_formal"],
  "matched_palettes": ["neutral", "monochrome"]
}
```

### 5.2 Agent 2：Style Strategy Agent（风格策略器）

**类型**：LLM Agent（受 Skill 约束）

**职责**：输出风格概率分布，为后续检索提供柔性偏好空间，同时受 Skill 约束裁剪。

**输入**：
```json
{
  "intent_plan": { "occasion": "面试", "style_intent": "formal + safe" },
  "user_state": { "preferred_styles": ["简约", "商务"] },
  "active_skill": { "skill_id": "business_formal", "color_rules": {...} }
}
```

**输出**：
```json
{
  "style_distribution": {
    "formal": 0.7,
    "business_casual": 0.2,
    "minimalist": 0.1,
    "street": 0.0,
    "sporty": 0.0
  },
  "color_preference": {
    "neutral": 0.8,
    "warm": 0.1,
    "cool": 0.1
  },
  "reasoning": "面试场景偏好正式、安全的风格，用户历史偏好简约商务"
}
```

**关键设计**：输出为概率分布，允许 Composer 在分布内采样，增加多样性。

### 5.3 Retriever Tool（检索工具）

**类型**：确定性 Tool

**职责**：从 Wardrobe 中召回 Top-30 候选，应用 Skill 硬约束。

**输入**：
```json
{
  "style_distribution": { "formal": 0.7, ... },
  "constraints": ["禁止牛仔裤", "正式度≥6"],
  "active_skill": { "category_rules": {...}, "formality_range": [7,9] },
  "top_k": 30
}
```

**过滤流程**：
1. 应用 Skill 品类约束（允许/禁止）
2. 应用正式度范围约束
3. 应用材质偏好约束
4. 向量检索 + 按品类均衡抽取

**输出**：Top-30 候选单品（已符合 Skill 规则）

### 5.4 Agent 3：Outfit Composer Agent（穿搭组合器）

**类型**：LLM Agent（生成型，受 Skill + Palette 约束）

**职责**：在受限候选池中生成 3 套差异化搭配方案，同时遵循 Skill 和 Palette 规则。

**输入**：
```json
{
  "candidates": [30件单品摘要],
  "style_distribution": { "formal": 0.7, ... },
  "active_skill": { "category_rules": {...} },
  "active_palette": { "color_rules": {...}, "type": "monochrome" },
  "constraints": ["正式度≥6"]
}
```

**Prompt 约束**：
- 单品选择必须来自候选池
- 必须遵循 Skill 的品类规则
- 色彩搭配应参考 Palette
- 3 套方案必须有明显差异化

**输出**：3 套 `OutfitPlan`

### 5.5 Agent 4：Outfit Critic Agent（评审器）

**类型**：确定性 Agent（含 Skill + Palette 适配度）

**职责**：5 维确定性评分 + 结构化报错。

**评分维度**：

| 维度 | 权重 | 计算方法 |
|------|------|----------|
| **色彩和谐** | 20% | 色相环距离 + 饱和度协调 + 明度层次 |
| **正式度匹配** | 20% | 方案正式度均值与 Skill 目标范围的偏差 |
| **风格一致性** | 20% | 各单品风格标签的聚类紧密度 |
| **材质协调** | 15% | 材质兼容性矩阵加权和 |
| **Skill 适配度** | 15% | 单品是否符合 Skill 的品类/色彩/材质规则 |
| **Palette 适配度** | 10% | 方案色彩是否符合 Palette 的色相/明度规则 |

**输出**：
```json
{
  "total": 82,
  "passed": true,
  "dimensions": {
    "color_harmony": 85,
    "formality_match": 80,
    "style_consistency": 90,
    "material_coherence": 75,
    "skill_alignment": 88,
    "palette_alignment": 70
  },
  "issues": []
}
```

### 5.6 Agent 5：Outfit Repair Agent（修复器）

**类型**：约束搜索 Agent（非 LLM）

**职责**：根据 Critic 的结构化报错，在候选池中做局部替换。替换时同时考虑 Skill 约束。

**输入**：
```json
{
  "outfit": { "item_ids": ["top_001", "bottom_003", "shoes_002"] },
  "issues": [{ "item_id": "top_001", "dimension": "color_harmony", "suggestion": "色相差60°以上" }],
  "active_skill": { "category_rules": {...} }
}
```

**替换策略**：
1. 识别被点名单品
2. 在候选中找同细分类的替代品
3. 按优化维度排序（色相差最大 / 正式度最接近 / 材质兼容性最高）
4. 同时验证替代品是否符合 Skill 约束
5. 替换并返回新方案

### 5.7 Memory：User State Tracker（记忆系统）

**类型**：非 Agent（持久化存储）

**职责**：记录用户偏好和历史，为其他 Agent 提供上下文。

**数据结构**：
```python
class UserState(BaseModel):
    user_id: str
    preferred_styles: List[str] = []
    avoided_categories: List[str] = []
    accepted_outfit_ids: List[str] = []
    rejected_outfit_ids: List[str] = []
    feedback_history: List[Dict] = []
    formality_preference: float = 5.0
    color_preference: str = "neutral"
```

### 6.3 路由逻辑

```python
def should_continue(state: GraphState) -> str:
    if state.is_passed:
        return "pass"
    if state.iteration >= state.max_iterations:
        return "fallback"
    return "repair"
```

### 6.4 熔断机制

| 触发条件 | 行为 |
|---------|------|
| 3 次 Repair 后 Critic 仍未通过 | 输出当前方案 + 标注“未完全通过，建议人工调整” |
| API 超时 | 降级到“仅规则检索 + 预设模板”模式 |

## 八、关键差异点（面试展示核心）

| 设计决策 | 为什么这样做 |
|---------|-------------|
| **知识层可插拔** | 新增风格或配色只需添加 YAML 文件，无需改代码，面试时可讲“配置驱动” |
| **只有 1 个 LLM Agent（Planner）** | 其他 Agent 用确定性规则/检索，保证系统可控、可解释 |
| **Critic 是硬编码，不是 LLM** | 保证评分可复现、可调试，面试时能讲清楚“确定性锚点” |
| **Repair 是局部搜索，不是重生成** | 系统最大的工程亮点——“手术式修复”比“重新投胎”稳定 |
| **LangGraph 状态机 + 条件路由** | 真正的多 Agent 调度，不是简单 pipeline |
